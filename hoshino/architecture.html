03 · 架构

原版内核，
原生外壳。

不 fork 内核。原版 DeepSeek Harness 跑在手机里的 Alpine 上；Kotlin 与 Compose 写成的原生界面，经本机回环与它对话。五层，各管一件事。

五层 · 自上而下

L5 · 界面

Kotlin + Jetpack Compose 原生界面

聊天、终端、设置全是原生绘制；声明式 UI 覆盖作用在这一层。

L4 · 桥

loopback WebSocket 桥 · @hh/bridge SDK

界面与内核只走本机回环；插件经 @hh/bridge SDK 调用 Android 能力：文件交付/分享、电量、通知、快捷方式、Intent、WebView 渲染。

L3 · 内核

原版 DeepSeek Harness 0.2.2-alpha.2 + Cordis（不 fork Agent loop）

原样运行；模型、工具、手机能力都是 Cordis 插件。

L2 · 运行时

源码编译 proot + Alpine 3.23 + Node 24

无需 root 的完整 Linux 用户空间，终端是真实 PTY。

L1 · 系统

Android

Keystore 保管 key，前台服务托住内核，Shizuku 开放系统命令。

数据流

一条请求，走四站。

  1. 01 · 界面Kotlin + Compose
  2. 02 · 桥loopback WebSocket
  3. 03 · 内核原版 dsh
  4. 04 · 模型provider · 你的 key

手机能力 · 反方向

  1. 01 · 内核原版 dsh 插件
  2. 02 · SDK@hh/bridge
  3. 03 · 系统Android 能力

中间没有 Hoshino 自己的服务器：无遥测、无 Google Play 服务、无远程业务后端。key 由你提供，存在 Android Keystore。

插件 · 示意

plugins/hello-tool.ts示意
export const name = 'hello-tool'
export function apply(ctx) {
  ctx.tool('hello', { description: '向用户问好' }, async ({ name }) => `你好，${name}`)
}

写一个插件，
就是写一个 Cordis 插件。

模型、工具、手机能力用的是同一套原版插件机制；内核不 fork，插件写法也不用另学。
