# 2026-10-05 参数、TTS 队列及翻唱复用修复

本轮保持角色资源、已验证的新版讲话（100 步、角色引导 0.7）及分离/声码器质量设置。

- 纯人声及 TTS 角色转换的移调、检索、辅音保护和 F0 控件不再因新版讲话被锁住。操作这些 RVC 参数明确选择兼容调音引擎，提交实际参数；人声音量与动态跟随仍可使用新版讲话。选择新版讲话可恢复原调。没有伪装新版讲话支持检索或 F0。
- 真实线上复现 TTS 提交返回 HTTP 429 / RVC_QUEUE_BUSY：两份翻唱占满任务槽。前端保留同一请求 ID 等待空位，遇临时连接故障恢复原请求；不会重复创建合成任务。总等待有 20 分钟上限。模型/语气/声线错误有具体说明。
- 翻唱结束后重新同步 TTS 控件，避免曾在忙碌状态检测服务后参数持续被禁用。
- 同一源文件的分离结果按输入、实际分离权重/配置、worker 代码及运行依赖版本 hash 复用。FLOAT WAV 原样复制，过期/损坏/不完整结果不命中；缓存 1 小时，最多 512 MiB，私有目录且随后台清理。普通翻唱、合唱和自动声区分析共用这一步。命中时保留已加载的 RVC 模型。
- 高低音跨度超过 18 半音的歌曲自动匹配保留原调；较窄歌曲的自动移调保留高低端余量。不逐帧改移调，不把合法高音折回八度，不增加宽中值滤波。日常讲话的跨音域匹配保留。此保护降低自动参数放大风险，不保证模型对所有极端唱法都不失真。

针对性验证包含参数提交、满队列重试幂等、TTS 控件恢复、自动匹配、合唱参数、缓存完整性/资源失效/寿命/容量及已有音高边界回归。真实生产音频和耗时证据保存于 `E:\大肥鱼\本轮功能修复\20261005`，与单元测试分开记录。首次分离仍使用完整模型；提速目标是重复转换及自动分析后的翻唱，不声称首次推理全面提速。
